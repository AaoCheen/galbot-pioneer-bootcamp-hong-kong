## 运行环境与探索顺序

脚本位于项目的 `scripts/sensors/` 目录。保留整个目录，包括 `common.py`，放到 HPU 已配置好的 SDK 环境再运行。用户本次实际运行目录为 `~/galbot-learning/sensors`：

```bash
cd ~/galbot-learning/sensors
python 01_sensor_inventory.py --sensor imu
python 02_imu_observe.py
python 01_sensor_inventory.py --sensor lidar
python 03_lidar_observe.py
python 01_sensor_inventory.py --sensor ultrasonic
python 04_ultrasonic_observe.py
python 05_sensor_health_check.py
```

上述目录来自用户终端输出；远端脚本由用户运行，助手未上传或远端执行。脚本依赖 Python 标准库和实机 `galbot_sdk.g1`，无需额外安装 NumPy。开发电脑上可用 `python3 文件名 --help` 看参数，但本地没有可直接运行的 macOS G1 SDK。

每次默认读取 10 轮，轮间等待 0.5 秒，初始化后等待 3 秒。一次只运行一个探索进程。所有脚本只初始化传感器并调用读取接口，退出时释放 SDK；没有底盘、手臂、头部或夹爪运动指令。读取也会占用通信和计算资源，先做单类实验，再做综合实验。

```bash
python 02_imu_observe.py --samples 30 --interval 0.2 --wait 5
python 02_imu_observe.py --imu CHASSIS_IMU
python 03_lidar_observe.py --output ~/galbot-learning/results
```

课程默认 `TORSO_IMU`，本地官方示例实际演示 `CHASSIS_IMU`，并注释列出 `LIDAR_IMU`。它们代表不同来源，不能把同名字段的读数混为一谈。脚本默认按课程用 `TORSO_IMU`，不自动替换；若为空，先查 SDK 和硬件配置，再显式尝试其他枚举。

## 输出与实验记录

每次运行生成 `scripts/sensors/output/时间_实验名/`：

- `readings.jsonl`：每次读取的传感器名、主机单调时刻、接口耗时、设备时间戳和数值摘要；异常保留原因。不是原始传感器全量包。
- `report.md`：自动观测结论，加上可手填的场景、预测、实际变化、待确认问题。
- 雷达实验额外提供 `last_frame.ply`：最后一帧成功解析的有限 XYZ。

每做一步，打开该次 `report.md`，用以下方式填写：

```text
场景：机器人静止；纸板在某探头前；未改变机器人姿态。
预测：纸板靠近时，对应方向距离应减小。
证据：填写实际传感器名、时间戳、前后读数；没有读到则写缺失。
解释：说明变化可能由什么导致，不把猜测写成实测事实。
待确认：单位、方向、量程、外参或时钟域。
```

报告会在正常结束及 Python 异常/中断时尽量保存已有记录；强制杀进程或断电不能保证保存。SDK 内部调用若阻塞，也可能需要终端中断及现场排查。

## 常见问题排查

1. `ModuleNotFoundError`：先确认使用 HPU 上能运行已有 G1 示例的同一 Python/虚拟环境。
2. 缺少枚举：检查当前版本，不能拿 G3/S1 的接口直接替代 G1。
3. init 失败：核对设备连接和 SDK 所需服务；不要先改配置或重启整机。
4. 数据为空：确认显式启用，增加 `--wait 5`；再核对该传感器实际是否发布。
5. 时间戳不推进：增加采样窗口；检查是否总在读缓存，并确认时间戳字段。
6. 点云解析失败：保留错误、fields 和跨度，核对实际布局；不直接把字节当 float32 四列强行读取。
7. 数值超出直觉：查单位、坐标系、无回波约定与安装方向，不能仅凭课程示例范围判坏。

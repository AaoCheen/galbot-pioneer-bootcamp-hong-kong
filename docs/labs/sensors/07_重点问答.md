## 学习过程中的关键问题

### “雷达已经有了两万个点，还是脚本存出来的？”

SDK 本次返回的一帧里已经包含 19968 条点记录。脚本负责读取和解析，不是从零开始一条条积累到两万个点。这里的“帧”是驱动返回的数据包组织单位，其具体采集窗口尚未核实。

```text
雷达采集 → 驱动组织点云 → SDK 返回一帧 → 脚本统计 → 保存最后成功帧
```

读取十次没有把它们拼成二十万点的地图；有重复缓存时甚至不是十个不同帧。`last_frame.ply` 仅保存最后成功帧的有限 XYZ。

### “一帧两万个点，就有两万个有效障碍物吗？”

不是。点是表面采样，多个点可以来自同一面墙。本次还包含约四千个零向量。点数、有效回波数、物体数量是不同概念；非零点也仍可能包含离群点、自体反射或其他无效回波。

### “为什么静止时加速度不是零？”

常见加速度计输出包含重力相关分量。安装姿态决定重力分到哪几个轴上，不能只看 Z 轴。本轮主要分量在 Z，但模长均值偏高还需独立核查。

### “距离或点数不变，就是没有更新吗？”

不是。场景静止时距离可以相同，驱动也可能采用固定点记录数量。应同时看时间戳和内容；时间戳推进仍不单独证明数据实时新鲜。

### “OBSERVED 和 positive_distance=true 是正常证明吗？”

前者是本脚本定义的基础观测状态；后者只是有限正数检查。它们不证明测量准确、量程有效，也不替代硬件验收或实际避障验证。

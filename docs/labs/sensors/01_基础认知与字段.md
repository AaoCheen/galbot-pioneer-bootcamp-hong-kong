## 三类传感器各看什么

把机器人想成在房间里观察环境的人：IMU 感受自己的转动和加速度；雷达测周围表面的三维位置；超声波测某个探头朝向上的近处距离。三者提供不同的信息。

| 传感器 | 读到什么 | 本次要回答什么 | 无法单独回答什么 |
|---|---|---|---|
| IMU | accel、gyro、magnet、时间戳 | 静止时基线怎样？数据是否推进？ | 周围障碍在哪、长期精确位置 |
| 雷达 | 含字段布局的二进制点云 | 有多少有效点？表面如何分布？ | 物体语义、外壳安全间距 |
| 超声波 | 某方向 distance 和时间戳 | 哪个探头随纸板距离变化？ | 完整三维形状、可靠确认无障碍 |

RGB 和深度图属于第九节，本组先完成第八节的三类传感器。

## 按需启用与实际返回结构

脚本：`01_sensor_inventory.py`。

**先预测**：启用 IMU 后，应该出现哪些字段？你预期加速度三个分量都为零吗？

**操作**：运行默认命令，查看 `SensorType` 名称、`init` 耗时、一次读取的 `read_ms`、实际 dict 字段。分别用 `--sensor lidar` 与 `--sensor ultrasonic` 查看其他返回格式。雷达的二进制 `data` 只打印类型和长度，避免刷屏。

**理解代码**：

```python
enabled = {SensorType.TORSO_IMU}
ok = robot.init(enabled)
imu = robot.get_imu_data(SensorType.TORSO_IMU)
```

集合声明这次需要接收的传感器。按本地示例，初始化时显式传入所需传感器，以减少接收和处理开销；不能据此断言硬件被断电或其他服务停止。

- 枚举存在：当前软件认识这个名字，不证明实机安装或启用。
- `init` 成功：SDK 初始化成功，不证明所有数据已就绪。
- 非空 dict：这次有内容，不证明字段有效、更新及时。
- `read_ms`：接口调用在本进程中的耗时，不是数据从采集到此刻的完整延迟。

首次脚本只读一次，报告出现“时间戳不足”是预期结果。

**记录**：IMU 的真实字段、雷达 `width/height/fields/point_step/row_step`、超声波 `distance` 是否出现。缺字段必须记为未知，不补零。

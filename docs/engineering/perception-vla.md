## 已完成的传感器探索

IMU、雷达和超声波分别提供自身运动相关量、环境表面几何和探头方向距离。本次用五个脚本逐步完成初始化、结构读取、连续观察和综合检查，详细结果见[传感器实测档案](../labs/sensors/README.md)。

最有价值的习惯是先核实字段、单位、坐标系和时间，再讨论感知算法。数据非空、数值有限、时间戳推进、测量准确是不同层面的证据。

## RGB 与深度：两种信息怎样对应

RGB 描述外观，深度提供几何线索。图像字节可能是压缩编码，必须按实际格式解码；深度数组的存储类型与比例系数共同决定物理单位。

一个像素的深度不能独立确定机器人坐标系下的抓取点，还需要内参、坐标约定及外参。RGB 和深度来自不同流时，要验证空间对齐与时间对应；无效深度也应保留标记。

课程材料中的相机示例用于研读。当前公开实测数据集中没有完整 RGB-D 采集实验，不将示例图像自动认定为本人运行结果。

## VLM 交互链路

```text
相机图像 → 图像解码 → 视觉语言理解 → 文本回答 → 语音或预设交互动作
```

VLM 可以解释画面，但文字回答不是机器人可直接执行的运动目标。流程中的语言输出和预设动作仍需要各自的接口与执行条件。这里整理链路与模块边界，不把课程模板的存在等同于已经完成整条链路。

## VLA 需要增加哪些工程环节

```text
图像 + 语言指令 + 机器人状态
        ↓ 策略模型（未来扩展）
动作解码：单位、顺序、坐标系、绝对量/增量、夹爪编码
        ↓
本地执行：约束检查、时序安排、状态反馈
        ↓
SDK / 控制服务 → 机器人 → 新观测
```

对接前要明确：动作是关节角还是末端位姿，归一化如何还原，多步动作如何调度，执行失败如何停止后续步骤。模型输入也由具体模型定义，不能因为机器人装有深度相机就假定策略接受 RGB-D。

本项目建立的是状态、观测和执行接口的基础理解，尚未实现或训练 VLA 策略。后续目标是让每一层都能被独立检查，并能追溯物理任务结果。

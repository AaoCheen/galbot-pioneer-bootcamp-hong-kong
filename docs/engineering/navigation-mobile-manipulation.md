# 导航与移动抓取：把接口组织成任务

[返回项目首页](../../README.md) · 对应课程 11—15

本篇整理官方课程与提供的 Day 2 示例，说明系统原理、任务编排和后续验证方式。当前未收录完整导航或移动抓取成功日志。

## 11｜SLAM 与三个坐标系

SLAM 同时估计自身位置并构建环境表示；在已保存地图中定位是另一个使用阶段。

- `map`：任务目标所在的全局参考系。
- `odom`：通常追求局部连续的里程计参考系，可能长期漂移。
- `base_link`：随机器人运动的本体参考系。

典型关系为 `map → odom → base_link → sensor/tool`。坐标变换连接这些表示，不能把雷达原点距离直接当成机身外壳距离，也不能把机器人前方的局部目标直接作为地图坐标发送。

## 12｜建图、后处理与重新定位

学习流程为采集环境几何、保存地图、检查杂点、加载地图和验证定位。后处理既要去掉临时物体，也要保留真实结构；地图版本与定位初始位姿应一起记录。

地图文件成功保存不代表定位稳定。后续实验应记录地图范围、定位反馈和异常恢复情况，而不是只留一张截图。

## 13｜一次导航需要什么条件

```text
定位有效 → 获取当前位姿 → 构造目标 → 检查可达性
         → 请求导航 → 观察返回状态与到达条件 → 记录最终位姿
```

请求被接受、导航过程结束、到达目标和满足操作精度是不同的条件。移动抓取还需要停靠后末端工作空间与物体位置匹配。

## 14｜相对目标与失败恢复

“向前移动”需要将本体参考系下的目标变换到导航使用的参考系。多路径点任务还需明确每一段的到达判据。

重试应有次数上限，并重新检查定位、目标和可达性。盲目重复同一个无效请求不会解决地图、阻挡或目标错误。

## 15｜移动抓取任务编排

```text
准备与定位 → NAV_TO_PICK → PICK → NAV_TO_PLACE → PLACE → 完成记录
                       任一阶段失败 → 停止后续阶段并记录原因
```

任务数据包括导航目标、机械臂关键姿态、夹爪参数、超时、重试以及分阶段结果。把这些放进结构化任务文件，能让“过程可执行”和“结果可追溯”同时成立。

本次提供的任务文件仍有 preplace、place 和放置导航目标为空，阶段完成字段也未标记成功。因此它支持任务结构分析，不能用来声明完整移动抓取已完成。现场视频单独展示机器人动作，不与这份不完整任务文件建立未经验证的对应关系。

## 下一轮实验应留下的证据

| 阶段 | 需要记录 |
|---|---|
| 导航到取料位 | 当前/目标位姿、定位情况、到达反馈 |
| 抓取 | 关键姿态、夹爪反馈、是否提起物体 |
| 导航到放置位 | 到达结果、携物状态、异常事件 |
| 放置 | 释放结果、物体稳定性、最终状态 |
| 重复实验 | 任务定义、试验次数、成功判据和失败类型 |

这些记录可进一步形成可比较的成功率和恢复能力评测；当前尚不填写推测的数字。
